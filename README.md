## 🎯 Лабораторна робота 1: Інтерактивна React-сторінка

### Список через `map()` та передача Props
Замість дублювання викликів компонентів застосовано декларативний рендеринг списку:
```jsx
{filteredCourses.map((course) => (
  <CourseCard
    key={course.id}
    id={course.id}
    title={course.title}
    instructor={course.instructor}
    duration={course.duration}
    description={course.description}
    isAvailable={course.isAvailable}
    category={course.category}
    level={course.level}
    rating={course.rating}
    availableSeats={course.availableSeats}
    accentColor={course.accentColor}
    isFavorite={favorites.includes(course.id)}
    onSelectDetails={handleSelectDetails}
    onToggleFavorite={handleToggleFavorite}
    onToggleEnroll={handleToggleEnroll}
  />
))}
```

### Екран деталей та навігація через стан
Навігація організована за допомогою стану React `selectedCourseId` (без сторонніх бібліотек, що відповідає темі заняття):
- `selectedCourseId === null`: показується каталог курсів або збережені курси;
- `selectedCourseId === number`: відкривається компонент `<CourseDetails />`.
- Пошук вибраного курсу:
  ```javascript
  const selectedCourse = courses.find((c) => c.id === selectedCourseId) || null;
  ```
- Кнопка повернення викликає `handleBackToList()` (`setSelectedCourseId(null)`).

### Умовне відображення доступності
- Якщо `isAvailable === true`: виводиться бейдж зеленого кольору **«Запис відкрито»**, вільні місця та активна кнопка «Записатися».
- Якщо `isAvailable === false`: виводиться бейдж червоного кольору **«Запис закрито»** та неактивна кнопка.

### Обробка неіснуючого курсу (404 стан)
Якщо передано неіснуючий `id` (наприклад, ID: 999):
```jsx
if (!course) {
  return (
    <div className="not-found-card">
      <h2>Помилка 404: Курс не існує</h2>
      <p>Курс з ідентифікатором #{requestedId} відсутній у базі даних...</p>
      <button onClick={onBack}>Повернутися до списку курсів</button>
    </div>
  );
}
```
Застосунок **не падає** із `TypeError: Cannot read properties of undefined`, а показує зрозуміле пояснення та шлях повернення. У інтерфейсі додано кнопку **«Тест 404 (ID 999)»** для наочної демонстрації викладачеві.

## 💾 Лабораторна робота 2: Локальні дані в React

### Стан `favorites`: вибір зберігання ID
У стані `favorites` зберігається **масив числових ID курсів** (`number[]`), наприклад `[1, 3]`.

> **Чому обрано зберігати ID, а не цілі об'єкти (аргумент для захисту):**
> 1. **Single Source of Truth (Єдине джерело істини):** Дані курсів зберігаються в масиві `courses`. Якщо зміниться назва курсу, викладач або статус запису («Запис відкрито» / «Запис закрито»), екран «Мої курси» завжди покаже актуальну інформацію завдяки `courses.filter(c => favorites.includes(c.id))`. При збереженні цілих об'єктів виникає ризик небезпечної розсинхронізації даних!
> 2. **Економія пам'яті:** У `localStorage` записується лише рядок `"[1,3]"`, а не надлишкові кілобайти дубльованого тексту.

### Захист від дублікатів
Функція перемикання перевіряє наявність ID у масиві перед додаванням:
```javascript
const handleToggleFavorite = (id) => {
  setFavorites((prevFavorites) => {
    if (prevFavorites.includes(id)) {
      // Вилучення
      return prevFavorites.filter((favId) => favId !== id);
    } else {
      // Додавання без створення дублікатів
      return [...prevFavorites, id];
    }
  });
};
```

### Секція «Мої курси» та порожній стан
Вгорі реалізовано таби перемикання між «Каталог курсів» та «Мої курси (Збережені) [лічильник]».
Якщо в обраному немає курсів (`favorites.length === 0`), рендериться спеціальний блок:
- Іконка збереженого матеріалу;
- Заголовок: **«Список обраного порожній»**;
- Пропозиція: *«Ви ще не додали жодного курсу. Перегляньте каталог та збережіть курси, що вас зацікавили...»*;
- Велика кнопка **«Перейти до каталогу курсів»**.

### Збереження та відновлення через `localStorage`
- **Читання (відновлення після перезавантаження):** виконується під час ініціалізації стану (Lazy initialization):
  ```javascript
  const [favorites, setFavorites] = useState(() => {
    try {
      const saved = localStorage.getItem('course_favorites_ids');
      return saved ? JSON.parse(saved) : [];
    } catch {
      return [];
    }
  });
  ```
- **Запис (миттєва персистентність):** виконується хуком `useEffect` при кожній зміні `favorites`:
  ```javascript
  useEffect(() => {
    try {
      localStorage.setItem('course_favorites_ids', JSON.stringify(favorites));
    } catch (e) {
      console.error(e);
    }
  }, [favorites]);
  ```
- **Навіщо `JSON.stringify` та `JSON.parse`:** Браузерний `localStorage` підтримує збереження **виключно рядків (DOMString)**. `JSON.stringify()` перетворює масив JavaScript `[1, 3]` у рядок `"[1,3]"`, а `JSON.parse()` парсить цей рядок назад у масив чисел.

## 🧪 Контрольний сценарій самоперевірки (Лаб 2)

Виконайте послідовно ці кроки:
1. **Зберегти два курси:** Натисніть сердечко на курсах 1 та 3. Лічильник у навігації показує «Мої курси (2)».
2. **Спробувати додати один із них повторно:** Повторний клік перемикає або зберігає без появи дублікатів.
3. **Перезавантажити сторінку (F5):** Обрані курси залишаються на місці, оскільки вони зчиталися з `localStorage`.
4. **Вилучити один курс і знову перезавантажити:** Залишається 1 курс, дані оновлюються в сховищі.
5. **Вилучити останній курс:** Список стає порожнім, з'являється інформаційне повідомлення з кнопкою повернення до каталогу.

## 💡 Матеріали для усного захисту перед викладачем

### Питання до Лабораторної роботи 1:
1. **Поясніть шлях одного значення:**
   `Об’єкт у масиві (title: 'React & Next.js')` ➔ перебір у `courses.map(course => ...)` ➔ передача через `title={course.title}` ➔ деструктуризація у `function CourseCard({ title })` ➔ виведення в JSX `<h3>{title}</h3>`.
2. **Як застосунок знаходить курс для детального екрана?**
   Через метод масиву `courses.find((course) => course.id === selectedCourseId)`.
3. **Як реалізовано обробку неіснуючого курсу?**
   Якщо `.find()` повертає `undefined`, у `CourseDetails` спрацьовує перевірка `if (!course) return <CourseNotFound ... />`, що запобігає падінню програми та надає користувачеві кнопку повернення.
4. **Швидка зміна на захисті:**
   - Додавання 4-го курсу: кнопка *«+ Додати 4-й курс»* викликає `setCourses([...courses, newCourse])` без зміни JSX.
   - Зміна статусу доступності: кнопка *«Змінити статус»* оновлює булеве поле `isAvailable`, що миттєво змінює текст бейджа та активність кнопки.

### Питання до Лабораторної роботи 2:
1. **Де знаходиться стан React і яка подія його змінює?**
   Стан `favorites` знаходиться в компоненті `App`. Його змінює подія `onClick` на кнопці «Зберегти курс» або іконці серця через функцію `handleToggleFavorite(id)`.
2. **Коли читається й записується localStorage?**
   - **Читається:** один раз під час завантаження компонента `App` (Lazy Initializer у `useState`).
   - **Записується:** у хуку `useEffect`, який реагує на кожну зміну залежності `[favorites]`.
3. **Навіщо потрібні `JSON.stringify()` та `JSON.parse()`?**
   `localStorage` працює тільки з рядками. `JSON.stringify()` перетворює масив у JSON-рядок перед збереженням, а `JSON.parse()` перетворює збережений рядок назад у масив JavaScript при завантаженні.

Відповідно до критеріїв оцінювання:
- **Де допоміг ШІ:**
  - Проєктування архітектури обробки неіснуючого `id` (404 state без падіння додатку);

  - Прийнято рішення зберігати лише масив `id` в `favorites` замість цілих об'єктів для запобігання розсинхронізації даних;

- **Що відхилено:**
  - Відхилено пропозицію зберігати повні об'єкти в `localStorage`, оскільки це призводило б до показу застарілої інформації при зміні курсу в базі.
